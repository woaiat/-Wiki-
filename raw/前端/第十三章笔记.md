**第 13 章：Components 组件** 。
这一章的主线非常清楚：

**组件就是可复用、可独立、可组合的页面模块。**

这一章一共 6 个核心例子，我一个都不跳，按例子来讲。

---

## 先记住这一章总目标

第 13 章不是在教你“再写一个页面”，而是在教你：

* 怎么把页面拆成小模块
* 怎么重复使用这些模块
* 怎么保证每个模块互不干扰
* 怎么控制组件的作用范围
* 怎么动态切换组件
* 怎么让组件对鼠标事件作出反应

---

## 1. 例子一：Simple Component

### 这个例子想证明什么

它想证明：

**组件就是一个可以反复拿来用的小 UI 块。**

### 例子结构

它有两个文件：

* `BasicComponent.vue`
* `App.vue`

### `BasicComponent.vue` 做了什么

它写了一个最简单的组件：

* `template` 里放一段标题和文字
* `script` 里只写了组件名
* `style scoped` 里给这个组件单独加绿色边框和背景

核心结构是：

```
<template>...</template>
<script>export default {...}</script>
<style scoped>...</style>
```

### 为什么这里要用 `scoped`

因为它表示：

**这些样式只作用于当前组件，不污染别的组件。**

这点很重要。
如果不用 `scoped`，样式可能跑到别的地方去。

### `App.vue` 做了什么

它先：

```
import BasicComponent from "./components/BasicComponent.vue";
```

然后：

```
components: { BasicComponent }
```

最后在模板里连续写了三次：

```
<BasicComponent />
<BasicComponent />
<BasicComponent />
```

### 这个例子的核心结论

同一个组件可以被重复使用很多次。
每次出现，都是这个组件的一个实例。

### 你该记什么

* 组件是可复用 UI 单元
* `.vue` 文件通常分成 `template / script / style`
* 要使用组件，一般要先 `import` 再注册
* `scoped` 样式只影响当前组件

## 2. 例子二：Data as a Function

### 这个例子想证明什么

这是第 13 章最重要的点之一。
它想证明：

**组件里的 `data` 必须写成函数，不能直接写成普通对象。**

### 为什么必须这样

如果你写成：

```
data: { count: 0 }
```

那多个组件实例会共享同一个对象。
这样点一个按钮，别的组件也可能一起变。

正确写法是：

```
data() {
  return { count: 0 }
}
```

### 这个例子里写了什么

`ClickCounter.vue` 里有：

* `count`
* `componentId`

模板里有：

```
<p>You clicked me: <strong>{{ count }}</strong> times</p>
<button @click="count++">Click Me!</button>
<p class="small">Component ID: {{ componentId }}</p>
```

### 这段代码怎么理解

* `{{ count }}`：把数据渲染到页面
* `@click="count++"`：点一次按钮，计数加一
* `componentId`：用随机值证明每个组件实例确实是独立的

### `App.vue` 里做了什么

还是连续放了三个：

```
<ClickCounter />
<ClickCounter />
<ClickCounter />
```

### 这个例子的关键现象

你点第一个计数器，只会第一个加一。
第二个和第三个不会变。

### 它到底在说明什么

这说明：

**每个组件实例都有自己独立的数据副本。**

这就是 `data()` 返回新对象的意义。

### 你该记什么

* 组件中的 `data` 要写成函数
* `data()` 返回一个新对象
* 这样每个实例的数据互不影响
* 这叫“状态隔离”或者“实例独立性”

## 3. 例子三：Local Registration

### 这个例子想证明什么

它想证明：

**局部注册的组件，只能在注册它的那个组件内部使用。**

### 例子结构

这里有：

* `SpecialButton.vue`
* `ParentBox.vue`
* `App.vue`

### `SpecialButton.vue` 是什么

就是一个简单按钮组件：

```
<button class="special-btn">Special Button (Local Only)</button>
```

### `ParentBox.vue` 做了什么

它先导入：

```
import SpecialButton from "./SpecialButton.vue";
```

然后局部注册：

```
components: { SpecialButton }
```

然后模板里使用：

```
<SpecialButton />
<SpecialButton />
```

### `App.vue` 做了什么

`App.vue` 只导入了 `ParentBox`，然后使用：

```
<ParentBox />
```

并且代码里明确提示：

```
<!-- <SpecialButton /> would FAIL -->
```

### 为什么会失败

因为 `SpecialButton` 只在 `ParentBox` 内部注册过。
它没有在 `App.vue` 里注册，所以 `App.vue` 直接写 `<SpecialButton />` 会报错。

### 这个例子的核心结论

局部注册的好处是：

* 作用范围明确
* 不容易和别的组件重名冲突
* 结构更清楚
* 更适合大多数普通组件

### 你该记什么

* 局部注册 = 只在当前组件内部能用
* 注册方式通常是 `components: { Xxx }`
* 大多数组件推荐局部注册

## 4. 例子四：Global Registration

### 这个例子想证明什么

它想证明：

**全局注册一次后，组件在整个应用里都能直接使用。**

### 注册发生在哪

不是在 `App.vue`，而是在 `main.js`：

```
const app = createApp(App);
app.component("GlobalAlert", GlobalAlert);
app.mount("#app");
```

### 这句最关键

```
app.component("GlobalAlert", GlobalAlert);
```

它表示：

把 `GlobalAlert` 注册成全局组件。

### `GlobalAlert.vue` 做了什么

这个组件做了一个通知框：

* 接收 `props`
* 有自己的内部状态 `isVisible`
* 有关闭按钮
* 点关闭按钮后隐藏自己

### 为什么这里又出现 `props`

因为组件不只是固定死内容，
它还可以通过外部传值变成不同内容。

例子里：

```
<GlobalAlert title="Welcome!" message="Globally registered!" />
<GlobalAlert title="Special Offer" message="Get 50% off!" />
```

### 这说明什么

同一个组件可以：

* 功能一样
* 但显示内容不一样

### `closeAlert()` 又说明了什么

它说明组件虽然是全局注册的，
但每个实例仍然有自己的内部状态。

点第一个关闭，不会把第二个也关掉。

### 你该记什么

* 全局注册写在 `main.js`
* 核心语句是 `app.component(...)`
* 全局注册后，不需要每个页面都再 `import`
* 适合高频复用组件，比如提示框、弹窗、通用按钮

## 5. 例子五：Dynamic Components

### 这个例子想证明什么

它想证明：

**组件可以在运行时动态切换。**

### 核心语法

```
<component :is="currentTab" />
```

这是这一节最关键的一句。

### 这句到底是什么意思

它表示：

当前到底渲染哪个组件，不是写死的，
而是由 `currentTab` 的值决定。

### 例子里有哪些组件

* `HomePage.vue`
* `AboutPage.vue`
* `ContactPage.vue`

还有一个控制器组件：

* `DynamicTabs.vue`

### `DynamicTabs.vue` 里怎么做的

它在 `data()` 里维护：

* `currentTab`
* `tabs`

比如：

```
currentTab: HomePage,
tabs: [
  { name: "Home", component: HomePage },
  { name: "About", component: AboutPage },
  { name: "Contact", component: ContactPage }
]
```

然后模板里：

```
<button v-for="tab in tabs" :key="tab.name"
  @click="currentTab = tab.component"
  :class="{ active: currentTab === tab.component }">
  {{ tab.name }}
</button>

<component :is="currentTab" />
```

### 这段代码怎么理解

* `v-for`：把所有 tab 按钮循环渲染出来
* `@click="currentTab = tab.component"`：点哪个按钮，就把当前组件换成哪个
* `:class="{ active: ... }"`：当前选中的按钮高亮
* `<component :is="currentTab" />`：真正渲染当前被选中的组件

### 这个例子的核心结论

这是一种“无路由标签切换”思路。

不需要页面跳转，也能切换不同组件内容。

### 你该记什么

* 动态组件核心写法是 `<component :is="...">`
* `v-for` 经常和它一起配合做 tab
* 点击按钮，本质上是在改当前组件变量

## 6. 例子六：Component Events – Mouse Interactions

### 这个例子想证明什么

它想证明：

**组件可以响应鼠标事件，并且每个实例依然是独立的。**

### 核心事件

* `@mouseover`
* `@mouseout`

### 例子组件

`InteractiveCard.vue`

模板里最关键的是：

```
<div class="interactive-card" @mouseover="handleMouseOver" @mouseout="handleMouseOut">
```

### 这句表示什么

* 鼠标移入这个卡片时，执行 `handleMouseOver`
* 鼠标移出时，执行 `handleMouseOut`

### 组件数据是什么

```
return {
  cityName: "Shanghai",
  isHovered: false,
  textColor: "blue"
}
```

### 鼠标移入时发生什么

```
handleMouseOver() {
  this.cityName = "Guizhou";
  this.isHovered = true;
  this.textColor = "red";
}
```

### 鼠标移出时发生什么

```
handleMouseOut() {
  this.cityName = "Shanghai";
  this.isHovered = false;
  this.textColor = "blue";
}
```

### 模板里如何体现这些变化

第一处：

```
<span :style="{ color: textColor }">{{ cityName }}</span>
```

说明：

* 文本颜色由 `textColor` 控制
* 显示的城市名由 `cityName` 控制

第二处：

```
<p v-if="isHovered" class="message">
  Mouse is over me! City changed to {{ cityName }}
</p>
```

说明：

* 只有 `isHovered` 为 `true` 时，这段提示才显示
* 这就是 `v-if` 的条件渲染

### 这个例子的另一个重点

它在 `App.vue` 里放了三个：

```
<InteractiveCard />
<InteractiveCard />
<InteractiveCard />
```

### 这想说明什么

你 hover 第一个卡片，第二个和第三个不会一起变化。

这再次证明：

**组件实例之间的数据是独立的。**

### 这个例子的 CSS 也有意义

* `transition: all 0.3s;`
* `:hover { transform: scale(1.02); }`
* `@keyframes fadeIn`

这说明组件不仅能处理逻辑，
还能把交互效果和样式打包在一起。

### 你该记什么

* `@mouseover` / `@mouseout` 是组件也能直接监听的事件
* `:style` 可以动态绑定样式
* `v-if` 可以根据状态控制内容是否显示
* 每个组件实例仍然互不影响

## 第 13 章总总结

这一章的 6 个例子，其实是在一步步回答“组件到底有什么用”：

1. `Simple Component`
   说明组件能复用
2. `Data as a Function`
   说明组件实例的数据必须独立
3. `Local Registration`
   说明组件可以只在局部使用
4. `Global Registration`
   说明组件也可以全局通用
5. `Dynamic Components`
   说明组件可以运行时切换
6. `Mouse Events`
   说明组件不仅能显示，还能响应交互

---

## 这章你最该死记住的 6 个点

* 组件是可复用 UI 模块
* `.vue` 文件一般有 `template / script / style`
* 组件里的 `data` 要写成函数
* 局部注册写在 `components: {}`
* 全局注册写在 `main.js` 的 `app.component(...)`
* 动态组件核心写法是 `<component :is="...">`

---

## 最简单总结一句

**第 13 章就是在学：如何把页面拆成独立小部件，并让这些小部件既能复用，又能各自独立工作。**
