# 第五章笔记：递归

这一章的核心不是“会背一个阶乘函数”，而是理解：

- 什么叫递归；
- 一个问题为什么适合递归；
- 递归函数为什么一定要有递归出口；
- 递归和栈到底是什么关系；
- 递归为什么能改成非递归。

一句话总纲：

**递归 = 把一个大问题，按相同规则拆成更小的同类问题，一直拆到可以直接求解为止。**

---

## 5.1 什么是递归

### 5.1.1 递归的定义

**定义：** 在定义一个过程或函数时，出现直接或间接调用自身的成分，称为递归。

按调用方式分三类：

- **直接递归**：函数直接调用自己；
- **间接递归**：A 调 B，B 再调 A；
- **尾递归**：递归调用语句是函数中最后一条执行语句。

### 先用最简单的例子理解原理：阶乘

课件里的阶乘例子最适合入门：

- `1! = 1`
- `n! = n × (n-1)!`

这就是一个标准递归定义。它天然分成两部分：

1. **递归出口**：什么时候不再继续往下拆；
2. **递归体**：当前问题如何转化成更小的同类问题。

对应代码：

```cpp
int fact(int n)
{
    if (n == 1)
        return 1;
    else
        return n * fact(n - 1);
}
```

这里：

- `if (n == 1) return 1;` 是递归出口；
- `return n * fact(n - 1);` 是递归体；
- 这也是一个 **直接递归**，而且是 **尾递归**（按课件表述）。

<blockquote>易错：没有递归出口，递归就不会停，最终会无限调用。</blockquote>

### 再看一个间接递归例子

如果：

- `A(n)` 调 `B(n-1)`
- `B(n)` 再调 `A(n-1)`

这就是间接递归。

本质没有变：

**问题还是在调用自己，只不过绕了个弯。**

---

## 5.1.2 什么时候使用递归

课件给了三个场景，这三个要按逻辑记。

### 1. 定义是递归的

如果一个问题本身的数学定义就是递归的，那么最自然的程序写法通常也是递归。

典型例子：

- 阶乘 `n!`
- Fibonacci 数列

例如 Fibonacci：

- `F(1)=1`
- `F(2)=1`
- `F(n)=F(n-1)+F(n-2)`，`n>2`

对应递归代码：

```cpp
int Fib1(int n)
{
    if (n == 1 || n == 2)
        return 1;
    else
        return Fib1(n - 1) + Fib1(n - 2);
}
```

这个例子能让你看到：

- 阶乘递归是“单分支递归”；
- Fibonacci 递归是“多分支递归”；
- 多分支递归会产生大量重复计算。

### 2. 数据结构是递归的

有些数据结构天然具有“一个部分里还嵌着同类结构”的特点，这时递归特别自然。

课件给的例子是：

- 单链表结点里有一个 `next` 指针，指向同类型结点。

这种结构本身就是递归定义的，所以很多操作都适合递归描述。

### 3. 问题的求解方法是递归的

这是最重要的一类。

也就是：

**大问题不能直接求，但可以拆成若干个更小、而且和原问题形式相同的小问题。**

典型例子：Hanoi（汉诺塔）问题。

---

## 5.1.3 递归思路与递归模型

### 先讲原理

课件里对递归思路的表述很准确：

**把一个不能或不好直接求解的大问题，转化成一个或几个小问题来解决；再把这些小问题继续分解，直到每个小问题都能直接解决。**

但递归分解不是乱拆，必须满足一个关键条件：

<span class="kp">大问题与小问题必须“同类”。</span>

也就是说，问题规模变小了，但求解规则不能变。

### 递归模型的两个组成部分

一般地，一个递归模型由两部分组成：

#### 1. 递归出口

决定递归在什么地方停止。

一般格式：

`f(s1) = m1`

这里 `s1` 和 `m1` 都是常量。

#### 2. 递归体

决定大问题如何递推到小问题。

所以你以后看到递归题，第一反应不是写代码，而是先问两件事：

- 递归出口是什么？
- 当前问题如何缩小为下一级问题？

### 例子 1：阶乘的递归模型

- 递归出口：`fun(1)=1`
- 递归体：`fun(n)=n*fun(n-1)`

### 例子 2：从特殊到一般理解“分解”

求 `5!`：

- `fun(5)` 要先求 `fun(4)`
- `fun(4)` 要先求 `fun(3)`
- `fun(3)` 要先求 `fun(2)`
- `fun(2)` 要先求 `fun(1)`
- `fun(1)=1`，到达出口

然后再一层层返回：

- `fun(2)=2×1=2`
- `fun(3)=3×2=6`
- `fun(4)=4×6=24`
- `fun(5)=5×24=120`

这说明递归总有两个方向：

- **分解过程**：一直向下拆；
- **求值过程**：从出口开始往回算。

### 例子 3：Fibonacci 为什么更难

求 `F(6)` 时：

- 要求 `F(5)` 和 `F(4)`；
- `F(5)` 又要求 `F(4)` 和 `F(3)`；
- `F(4)` 又要求 `F(3)` 和 `F(2)`。

于是会出现大量重复子问题，比如 `F(4)`、`F(3)` 被反复求。

这解释了为什么：

<span class="kp">不是所有递归都高效，递归的表达自然，不代表时间效率高。</span>

## 5.1.4 递归与数学归纳法

这一节课件强调的是“思想联系”。

### 原理

从递归体看：

- 如果已知 `s_i, s_{i+1}, ..., s_{n-1}`，就可以推出 `s_n`；
- 从数学归纳法角度看，这对应“归纳步骤”；
- 同时还必须给出初值 `s_1`，这对应“递归出口”。

所以：

<span class="kp">数学归纳法是递归求解问题的理论基础，递归思想可以看作程序设计中的归纳法实现。</span>

### 课件里的结论

- 数学归纳法是一种论证方法；
- 递归是一种算法和程序设计技术；
- 递归思想来自数学归纳法。

这个地方考试一般不是让你证明定理，而是让你说出两者关系。

## 5.1.5 Hanoi 问题：递归最经典的应用题

### 先讲原理

Hanoi 问题里：

- 有三根柱子 `X, Y, Z`
- `X` 上有 `n` 个盘片，从小到大叠放
- 要把它们全部移到 `Z`
- 规则是：
  1. 每次只能移动一个盘；
  2. 任何时刻大盘不能放在小盘上面。

### 再讲应用步骤

如果定义：

`Hanoi(n, X, Y, Z)` 表示“把 `n` 个盘子从 `X` 借助 `Y` 移到 `Z`”

那么求解步骤是：

1. 先把上面的 `n-1` 个盘子，从 `X` 借助 `Z` 移到 `Y`
2. 再把最大的第 `n` 个盘子，从 `X` 直接移到 `Z`
3. 最后把 `Y` 上的 `n-1` 个盘子，借助 `X` 移到 `Z`

也就是：

- `Hanoi(n-1, X, Z, Y)`
- `move(n, X, Z)`
- `Hanoi(n-1, Y, X, Z)`

### 用简单例子理解

如果是 `n=2`：

- 先把盘 1 从 `X` 移到 `Y`
- 再把盘 2 从 `X` 移到 `Z`
- 再把盘 1 从 `Y` 移到 `Z`

如果是 `n=3`：

- 先把上面两个盘当作一个“小问题”处理
- 再搬最大盘
- 再把那两个盘搬回来

你会发现：

**大问题的结构和小问题完全一样，只是盘子数量从 `n` 变成了 `n-1`。**

这正是递归适用的根本原因。

### 递归次数

课件给出的递推式：

- `t(1)=1`
- `t(n)=2t(n-1)+1`，当 `n>1`

例如移动 6 个盘子：

最终可得：

`t(6)=2^6-1=63`

这个结果也要记住：

<span class="kp">Hanoi 移动 `n` 个盘子最少需要 `2^n - 1` 次。</span>

## 5.2 栈与递归

这一节讲的是：**为什么递归能用栈实现。**

### 原理

递归调用过程中，每进入一层函数，都要保存现场信息，比如：

- 参数值
- 返回地址
- 局部变量
- 中间结果

这些信息必须按“后调用先返回”的顺序处理。

而这正好符合：

<span class="kp">栈的后进先出（LIFO）特性。</span>

所以：

**递归可以用栈来实现。**

### 用阶乘例子理解

`fact(4)` 调用过程：

- `fact(4)` 调 `fact(3)`
- `fact(3)` 调 `fact(2)`
- `fact(2)` 调 `fact(1)`

你可以把这理解成“每调用一次，就压栈一次”。

压栈顺序是：

- `fact(4)`
- `fact(3)`
- `fact(2)`
- `fact(1)`

到达出口后再反向出栈计算：

- `fact(1)=1`
- `fact(2)=2×1=2`
- `fact(3)=3×2=6`
- `fact(4)=4×6=24`

所以：

<span class="kp">递归的“分解过程”对应压栈，递归的“返回求值过程”对应出栈。</span>

### 递归如何转为非递归

课件这里给了两个结论：

- 一般递归算法可以通过**栈**转为非递归形式；
- **尾递归**可以直接用**循环递推**的方法转换。

这也是为什么：

- 普通递归常常和“显式栈”对应；
- 尾递归常常能直接改写成 `while` / `for` 循环。

## 第五章终极复习总结

### 一句话概括

<span class="kp">递归就是把大问题按相同规则拆成更小的同类问题，直到到达递归出口；其运行过程本质上依赖栈保存现场。</span>

### 必记内容

1. 递归的定义：直接递归、间接递归、尾递归。
2. 什么时候适合用递归：
   - 定义递归的；
   - 数据结构递归的；
   - 求解方法递归的。
3. 递归模型由两部分组成：
   - 递归出口；
   - 递归体。
4. Hanoi 问题的递归拆分。
5. `t(n)=2t(n-1)+1`，Hanoi 最少移动次数为 `2^n-1`。
6. 递归与数学归纳法的关系。
7. 递归与栈的关系。
8. 递归如何转非递归：一般靠栈，尾递归可改循环。

## 易错点清单

1. 递归不是“函数里出现自己”这么简单，必须还能停下来，所以一定要有递归出口。
2. 间接递归也是递归，不要求必须函数名直接调用自己。
3. 递归分解不是随便拆，必须保证“大问题”和“小问题”同类。
4. 递归表达自然，不等于一定高效；Fibonacci 递归会产生大量重复计算。
5. 数学归纳法和递归不是一回事：
   - 数学归纳法是证明方法；
   - 递归是程序设计方法。
6. 递归与栈的关系不能只背一句“有关”，要能说出：每一层调用都要保存现场，因此符合栈的后进先出。
