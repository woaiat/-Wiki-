 1. What is VueJS?

 3. Understanding DOM & Virtual DOM

What is DOM (Document Object Model)?
The Document Object Model, or DOM, is an interface that treats all markup language (your HTML) as
connected nodes. It can be seen as an interface of objects for markup elements stored in a tree-like
structure.

The DOM allows us to write and change styles on elements, and even change elements themselves. This is
done by adding, modifying, or deleting element tags or CSS styles in the head and body of a document
because they are represented as nodes and objects.

⚠ Disadvantages of Traditional DOM
As applications grow, more nodes to traverse, more elements, and more scripts to communicate with those
elements — the DOM grows slower and costs a lot of processing power. Trying to perform a search or even
update a DOM becomes a hard task, ultimately affecting the performance of the application.




                                    How Vue.js Virtual DOM Works


        Step 1         Initial Render

      Vue creates a Virtual DOM from the template and renders it to the real DOM.

         Template
        <div id="app">
            <h1>{{ title }}</h1>
            <p>{{ message }}</p>
          <button @click="update">Update</button>
        </div>



                                                     →
         Virtual DOM (in memory)
        • div#app
        •   h1 → "Hello Vue!"
        •    p → "This is Vue.js"
        •    button → "Update"




        Step 2         Data Changes

      When data changes, Vue creates a new Virtual DOM (New VDOM).

         Data Change
        // change
 this.message = 'Virtual DOM is awesome!'




  New Virtual DOM (in memory)
 <div id="app">
   <h1>Hello Vue!</h1>
  <p>Virtual DOM is awesome!</p>
   <button>Update</button>
 </div>




 Step 3       Diffing (Compare)

Vue compares the New VDOM with the Old VDOM to find the minimal changes.

  Old Virtual DOM
 <div id="app">
  <h1>Hello Vue!</h1>
  <p>This is Vue.js</p>
  <button>Update</button>
 </div>



                                                  ↔
  New Virtual DOM
 <div id="app">
  <h1>Hello Vue!</h1>
  <p>Virtual DOM is awesome!</p>
   <button>Update</button>
 </div>




  Diff Result: Only the <p> tag content changed from "This is Vue.js" to "Virtual DOM is awesome!"




 Step 4       Patch

Vue creates a patch (instructions) with only the necessary changes.

  Patch (instructions):
 - Set <p> text to 'Virtual DOM is awesome!'




 Step 5       Apply Patch to Real DOM

Vue applies the patch to the real DOM. Only the changed part is updated.

  Real DOM (in browser)
 <div id="app">
  <h1>Hello Vue!</h1>
  <p>Virtual DOM is awesome!</p>
   <button>Update</button>
 </div>




 Step 6       DOM is in Sync

The real DOM is now in sync with the latest data. UI is updated with minimal
operations.

  Final Real DOM (in browser)
 <div id="app">
  <h1>Hello Vue!</h1>
  <p>Virtual DOM is awesome!</p>
  <button>Update</button>
 </div>




Benefits of Virtual DOM:
        Better Performance
        Minimal DOM operations
        Faster UI updates
        More efficient




       Summary: Vue uses Virtual DOM as an intermediary layer. When data changes, it updates the
      Virtual DOM, compares it with the previous one (diffing), creates a patch, and applies only the
      necessary changes to the Real DOM.

 1. Simple Component – Reusable Building Block


 Theory: Components are independent, reusable pieces of UI. In Vue 3, a component encapsulates HTML
(template), logic (script), and scoped styles. Components help split the UI into manageable pieces and can be
nested. Each component instance maintains its own state when data is a function.

Local registration: import component and add to components option.
Template: defines HTML structure with Vue directives.
Scoped styles: CSS that applies only to this component.




//   src/components/BasicComponent.vue

    <div class="my-component">
     <h1>This is coming from component</h1>
     <p>Hello! I am a reusable component.</p>
    </div>

export default {
    name: "BasicComponent",

</script>


<style scoped>
.my-component {
    border: 2px solid green;

    margin: 10px;
    background-color: #e8f5e9;
    border-radius: 10px;
}
</style>

     <h1>My Vue 3 App</h1>

 2. Data as a Function – Independent State Isolation


⚠ Critical Concept: In Vue components, data must be a function that returns a fresh object. If it were a plain
object, all instances would share the same reference, causing mutations to affect every component. This
pattern guarantees each instance has its own private reactive scope.

data() { return { count: 0 } } → correct.
data: { count: 0 } → wrong (Vue 3 throws warning).

 3. Local Registration – Scope & Encapsulation


Local Registration means a component is available only inside the component where it is registered (via
components option). This prevents global conflicts, improves bundle splitting, and makes dependencies explicit.
It's the recommended way for most components.



//   src/components/SpecialButton.vue
<template>
    <button class="special-btn"> Special Button (Local Only)</button>
</template>


<script>
export default { name: "SpecialButton" };
</script>

    color: white;
    padding: 10px 20px;
    border: none;
    border-radius: 5px;
    margin: 5px;
    cursor: pointer;
}
</style>


//   src/components/ParentBox.vue
<template>
    <div class="parent-box">
     <h3>Parent Component</h3>
     <p>This component can use SpecialButton because I registered it here:</p>
     <SpecialButton />
     <SpecialButton />
    </div>
</template>


<script>
import SpecialButton from "./SpecialButton.vue";
export default {
    name: "ParentBox",

.parent-box {

 4. Global Registration – One-Time, Use Everywhere


 Global Components are registered using app.component('name', Component) in main.js. After registration, they
can be used in any component template without importing. Best for high-frequency UI pieces (alerts, modals,
buttons). Vue 3 migrated from Vue.component to app.component.



//   main.js
import { createApp } from "vue";
import App from "./App.vue";
import GlobalAlert from "./components/GlobalAlert.vue";


const app = createApp(App);
app.component("GlobalAlert", GlobalAlert);   //   GLOBAL REGISTRATION
app.mount("#app");


//   src/components/GlobalAlert.vue
<template>
  <div class="alert-box" v-if="isVisible">
     <div class="alert-icon"></div>
     <div class="alert-content">
      <h3>{{ title }}</h3>
      <p>{{ message }}</p>
     </div>
     <button class="close-btn" @click="closeAlert">✖</button>
  </div>
</template>


<script>
export default {
  name: "GlobalAlert",
  props: { title: { type: String, default: "Notification" }, message: { type: String, default: "This is a global alert component!" }
},
  data() { return { isVisible: true }; },
  methods: { closeAlert() { this.isVisible = false; } }
};
</script>


// App.vue – no import needed!
<template>
  <div id="app">
     <h1> Global Registration Demo</h1>
     <GlobalAlert title="Welcome!" message="Globally registered!" />
     <GlobalAlert title="Special Offer" message="Get 50% off!" />
  </div>
</template>




 Explanation: After app.component(), the GlobalAlert component becomes globally available. You never need to import it in
any component. The alert has internal state (isVisible) and a close button that hides it — demonstrating encapsulated
behavior.

        1. Basic Click Event – Handling Button Clicks


 Theory: Events in Vue.js are used to respond to user actions like clicks, mouse movements, keyboard

Syntax: <button v-on:click="methodName">Click Me</button>

Common events: submit, keyup, drag, scroll, error, abort, mouseover, mouseout, load

      2. .once Event Modiﬁer – Execute Only Once


Theory: Event modifiers are directive postfixes denoted by a dot (e.g., .once, .prevent, .stop). The .once
modifier allows an event to execute only once. After the first click, subsequent clicks have no effect.

Common modifiers: .once · .prevent · .stop · .capture · .self · .passive




//    Vue 3 Component - OnceModifierDemo.vue
<template>
  <div class="demo-container">
      <button @click.once="buttonClickedOnce" :style="styleobj">
          Just once clickable
      </button>
      <p>Output: {{ clickNum }}</p>


      <button @click="buttonClicked" :style="styleobj">
          Click Me anytime
      </button>
      <p>Output: {{ clickNum1 }}</p>
  </div>
</template>


<script>
export default {
  name: "OnceModifierDemo",
  data() {
      return {
          clickNum: 0,
          clickNum1: 0,
          styleobj: {
              backgroundColor: "#2196F3",
              cursor: "pointer",
              padding: "8px 16px",
              verticalAlign: "middle",
              border: "none",
              borderRadius: "4px",
              color: "white"
          }
      };
  },
  methods: {
      buttonClickedOnce() {
          this.clickNum++;
      },
      buttonClicked() {
          this.clickNum1++;
      }
  }
};
</script>




Explanation: The first button uses @click.once — it increments clickNum only on the first click. Subsequent clicks do
nothing. The second button uses regular @click — it increments clickNum1 every time it's clicked.

 3. .prevent Event Modifier – Prevent Default Behavior


Theory: The .prevent modifier calls event.preventDefault() internally. It's used when you don't want the
browser's default action to occur (e.g., following a link, submitting a form).



//    Vue 3 Component - PreventModifierDemo.vue
<template>
  <div>
      <!-- WITH .prevent — won't navigate -->
      <a href="http://www.google.com" @click.prevent="clickMe" target="_blank" :style="styleobj">
          Click Me (With .prevent)
      </a>


      <!-- WITHOUT .prevent — will navigate -->
      <a href="http://www.google.com" @click="clickMeWithoutPrevent" target="_blank" :style="styleobj">
          Click Me (Without .prevent)
      </a>
  </div>
</template>


<script>
export default {
  name: "PreventModifierDemo",
  data() {
      return {
          styleobj: {
              color: "#4CAF50",
              marginLeft: "20px",
              fontSize: "30px",
              display: "inline-block",
              marginRight: "20px"
          }
      };
  },
  methods: {
      clickMe() {
          alert("Anchor tag is clicked! Navigation PREVENTED!");
      },
      clickMeWithoutPrevent() {
          alert("This will navigate to Google after this alert");
      }
  }
};
</script>




 Explanation: The first link uses @click.prevent — it shows an alert but does NOT navigate to Google. The second link uses
regular @click — it shows an alert AND then navigates to Google.

⌨ 4. Key Modiﬁers – Handling Keyboard Events


Theory: Key modifiers are used to handle specific keyboard keys. Vue provides built-in key modifiers like
.enter, .tab, .delete, .esc, .space, .up, .down, .left, .right. You can also chain multiple modifiers like
@keyup.ctrl.enter.




//   Vue 3 Component - KeyModifiersDemo.vue
<template>

     <input

      v-model="tempName"
     />
     <h3>Your name: {{ name }}</h3>


     <h3>Press Ctrl + Enter</h3>
     <input
      type="text"
      @keyup.ctrl.enter="showInputValueCtrl"
      :style="styleobj"
      placeholder="Type something and press Ctrl+Enter"
      v-model="tempMessage"
     />
     <h3>Message: {{ message }}</h3>


     <div class="key-list">
      <span class="key-badge">.enter</span>
      <span class="key-badge">.tab</span>
      <span class="key-badge">.delete</span>
      <span class="key-badge">.esc</span>
      <span class="key-badge">.space</span>
      <span class="key-badge">.up</span>
      <span class="key-badge">.down</span>
      <span class="key-badge">.left</span>
      <span class="key-badge">.right</span>
     </div>
  </div>
</template>


<script>
export default {
  name: "KeyModifiersDemo",
  data() {
     return {
      name: "",
      tempName: "",
      message: "",
      tempMessage: "",
          styleobj: {
              width: "100%",
              padding: "12px 20px",
              margin: "8px 0",

</script>




Explanation: The first input uses @keyup.enter — the value appears ONLY when you press the Enter key. The second input

 5. Custom Events – Child to Parent Communication


 Theory: Custom events allow child components to communicate with parent components. The child uses
$emit('event-name', data) to send data upward. The parent listens using @event-name="handlerMethod". This is the
standard way for child-to-parent communication in Vue.



//    Vue 3 Child Component - LanguageButton.vue
<template>
  <button @click="displayLanguage" class="language-btn">
      <span style="font-size:25px;">{{ item }}</span>
  </button>
</template>


<script>
export default {
  name: "LanguageButton",
  props: ["item"],
  methods: {
      displayLanguage() {
          this.$emit('showLanguage', this.item);
      }
  }
};
</script>
//    Parent Component - CustomEventsDemo.vue
<template>
  <div>
      <p style="font-size:25px;">
          Language displayed : <b>{{ languageClicked }}</b>
      </p>
      <div class="languages-grid">
          <LanguageButton
           v-for="(item, index) in languages"
           :key="index"
           :item="item"
           @showLanguage="languageDisp"
          />
      </div>
  </div>
</template>


<script>
import LanguageButton from "./LanguageButton.vue";


export default {
  name: "CustomEventsDemo",
  components: { LanguageButton },
  data() {
      return {
          languageClicked: "",
          languages: ["Java", "C", "C++", "Python", "Javascript", "Angular", "Data Structure", "jQuery"]
      };
  },
  methods: {
      languageDisp(language) {
          this.languageClicked = language;
          console.log("Language selected:", language);
      }
  }
};
</script>




 Explanation: The child component (LanguageButton) receives a item prop and emits a custom showLanguage event when
clicked. The parent listens with @showLanguage="languageDisp" and updates languageClicked to display the selected language.




⚡ Live Demo: Custom Events (Parent-Child Communication)


       Click any language button — the selected language appears above. This is child-to-parent communication using
       $emit.
