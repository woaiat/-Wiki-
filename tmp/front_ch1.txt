1. HTML5 Document Structure
HTML is the language used to define the structure and content of a webpage. A valid HTML5 page begins with a
document type declaration, then the root element, then the head and body sections.

Example: Basic HTML5 page structure
           <!DOCTYPE html>
           <html>
           <head>
             <meta charset="UTF-8">
             <title>Document Title</title>
             <link rel="stylesheet" href="styles.css">
             <script src="app.js"></script>
           </head>
           <body>
             <h1>Welcome</h1>
             <p>Visible content goes here.</p>
           </body>
           </html>


    Actual browser output
    Browser tab: Document Title


    Welcome
    Visible content goes here.

                Part                                                                    Role

   <!DOCTYPE html>                   Declares HTML5 and tells the browser to use standards mode. It should appear first.

   <html>                            Root element that wraps the complete HTML document.

   <head>                            Contains metadata, title, links to CSS, scripts, charset, and other information not normally shown
                                     as page content.

   <title>                           Sets the text visible on the browser tab or page title area.

   <body>                            Contains visible content such as text, headings, images, links, tables, forms, and components.

    Key point

    The <head> section stores metadata and resource links. The <body> section stores what users actually
    see in the browser window.

3. Semantic HTML5 Tags
Semantic tags clearly describe the meaning of content. They improve readability, accessibility, and search-engine
understanding. Unlike old presentational tags such as <font>, semantic tags explain the page structure.

              Semantic tag                                                    Purpose

   <header>                     Introductory area of a page or section, often containing logo, title, or navigation.

   <nav>                        Navigation links such as menu items or table of contents.

   <article>                    Independent, self-contained content such as a blog post or news item.

   <aside>                      Side content related to the main content, such as notes, ads, or sidebars.

   <section>                    Thematic grouping of related content.

   <footer>                     Footer information such as copyright, contact, or related links.

6. HTML Tables

7. HTML Forms and Validation
Forms collect user input and submit it to a server or process it with JavaScript. The <form> tag usually works with
attributes such as action, method, target, and enctype.

              Form concept                                                 Explanation

   <form>                       Main container used to collect and submit user input.

   GET method                   Appends form data to the URL. Useful for simple, non-sensitive requests.

   POST method                  Sends form data in the request body. Better for larger or sensitive data.

   required                     Makes a field mandatory before submission.

   placeholder                  Displays a hint inside the field.

   pattern                      Defines a regular-expression pattern for validating input.

   datalist                     Provides predefined suggestions for an input field.

   <optgroup>                   Groups related options inside a drop-down list.

                   Control                                                         Use

   <input type="text">                Single-line text such as name or address.

   <input type="password">            Hides typed characters for password entry.

   <input type="radio">               Lets the user select only one option from a group sharing the same name.

   <input type="checkbox">            Lets the user select one or more options.

   <input type="email">               Collects email address and provides built-in validation.

   <input type="url">                 Collects URL and provides built-in validation.

   <input type="number">              Collects numeric input and can use min/max.

   <input type="date">                Collects a date value using the browser date control when supported.

   <input type="submit">              Creates a submit button for sending form data.

   <input type="tel">                 Collects telephone numbers; validation depends on extra rules.

   <select>                           Creates a drop-down list; <optgroup> can group related options.

           <button type="submit">Submit</button>

8. JavaScript and jQuery Essentials
JavaScript adds behaviour to web pages. It can read user input, validate forms, change HTML/CSS dynamically,
and respond to events. Basic building blocks include variables, functions, loops, and conditions.

                     Concept                                                       Explanation

   document.getElementById("id")                Common JavaScript method for selecting an element by id.

   Variables                                    Store data values.

   Functions                                    Reusable blocks of code.

   Loops                                        Repeat code.

   Conditions                                   Run code depending on true/false logic.

jQuery is a JavaScript library that simplifies DOM selection, events, and effects.

                    jQuery syntax                                                         Meaning

   $(document).ready(function(){ ... })             Runs code only after the DOM tree has been fully constructed.

   $("#myButton").click(function(){ ... })          Attaches a click handler to the selected element.

   $("#myButton").click()                           Triggers the click event programmatically when no function is passed.

   .slideToggle()                                   Slides an element up or down, toggling between hidden and visible.

    Important note

    .slideToggle() is not only for sliding up. It toggles: if the element is visible, it slides up; if hidden, it slides
    down.

10. Vue 3 and Vue CLI
Vue.js is a progressive JavaScript framework for building user interfaces. Vue 3 commonly uses components,
reactivity, directives, and a virtual DOM to create efficient and maintainable web applications.

                  Vue feature                                                           Meaning

   Reactivity system                         Vue tracks data changes and updates the DOM automatically.



                                                                                                                Page 8 of 10
Web Frontend Development Technology - Revision Notes



                 Vue feature                                                     Meaning

   Component-based architecture       UI is built using reusable components with their own template, logic, and style.

   Declarative rendering              Templates describe what the UI should look like based on data.

   Directives                         Special attributes such as v-if, v-for, v-bind, v-on, and v-model.

   Two-way data binding               v-model keeps form input and component data synchronized.

   Virtual DOM                        Vue calculates efficient UI updates before changing the real DOM.

             Directive / option                                                   Use

   data()                          Returns the reactive state object for each component instance. Each instance should have
                                   separate data.

   {{ }} interpolation             Displays data in the template.

   v-bind                          Binds data to HTML attributes. Shorthand is :.

   v-on                            Handles events. Shorthand is @.

   v-model                         Creates two-way binding with form controls.

   v-for                           Renders a list by iterating over an array.

   v-if                            Conditionally renders an element.

   v-else / v-else-if              Alternative conditional branches.

   v-show                          Conditionally displays an element using CSS display.

   v-once                          Renders an element once and then skips future updates.

    v-once correction

    v-once does not force re-rendering. It does the opposite: it renders the element once and then keeps it
    static, even if related data changes.

Component registration can be global or local:

             Registration type                                                  Meaning

   Global registration              Done with app.component("ComponentName", Component) in main.js. The component is
                                    available throughout the app.

   Local registration               Component is available only inside the component where it is imported and registered. It is
                                    recommended for most components to reduce naming conflicts and unnecessary global
                                    scope.

Common Vue CLI commands and project files:

                        Item                                                     Purpose

   npm run serve                      Runs the development server.

   App.vue                            Root component in a Vue CLI project.

   main.js                            Entry file where the Vue app is created and mounted.

   src folder                         Main source code folder for components and application logic.

   public folder                      Static assets and public index file.

   package.json                       Project scripts and dependency information.

   node_modules                       Installed project dependencies.

1. Introduction to CSS

   cascading style sheets      CSS is a collection of styles that allows you to change the appearance
of HTML elements on Web pages. It defines standard rules for layout and appearance, ensuring
consistent design across a website.




        Why CSS? Better control over page layout, enforce consistent display, separate content
     from presentation.




     Syntax of a CSS rule


    selector {
        property: value;
        /* multiple declarations */
    }



Example: make all <h1> red and italic, all <h2> bold.



    h1 { color: red; font-style: italic; }
    h2 { font-weight: bold; }




                            Welcome
          result
                            Subheading




2. Types of style sheets
Three ways to apply CSS: inline, internal (embedded), external.



    ✏ Inline style
Applied directly to an element using the     style   attribute. Highest priority.



    <P style="font-size:24pt; color:red;">Hotel booking from the comfort of your room.
    </P>




       Hotel booking from the comfort of your room.




     Internal (embedded) style sheet
Defined inside    <STYLE>   in the    <HEAD> . Affects that page only.



    <STYLE>
      p { color:red; font-size:20pt; font-style:italic; }
    </STYLE>




     External style sheet
Separate   .css    file linked via   <LINK> . Best for multi‑page consistency.



    <LINK type="text/css" rel="stylesheet" href="externalstyle.css">



externalstyle.css content:



    p { color:red; font-size:20pt; }
    h1 { color:blue; font-weight:bold; }




    ⚖ Priority of style sheets (descending)

1. Inline style (highest)
2. Internal style sheet
3. External style sheet
4. Browser default
     If same selector appears in multiple sheets, the most specific (highest priority) wins.




3. CSS selectors – ID and class


     ID selector (#)

Chapter 12 - Introduction to VueJS


 1. What is VueJS?

VueJS (pronounced "view") is an open-source progressive JavaScript framework used to develop interactive
web interfaces. It is one of the most famous frameworks used to simplify web development.

Progressive Framework: You can start small and scale up as needed
Approachable: If you know HTML, CSS & JavaScript, you're ready to develop Vue apps in no time
Versatile: Can be embedded into any web app or existing project
Lightweight: Only 20KB min+gzipped runtime blazing fast framework
Perfect for SPAs: Ideal for building Single Page Applications


   Key Point: Vue focuses on the view layer only, making it easy to integrate with other libraries or
  existing projects.




⚡ 2. Features of VueJS


    Virtual DOM
  A "lite" version of HTML DOM that uses diff algorithms to avoid re-rendering the entire DOM after
  changes.



   Data Binding

  Manipulate HTML attributes, change style, and assign classes using the v-bind directive.



   Components

  Create custom, reusable elements that can be used in HTML.



   Event Handling

   v-on attribute listens to DOM events in VueJS.



   Animation/Transition

  Built-in transition component with third-party animation library support.



   Computed Properties

  Listen to UI changes and perform calculations without additional coding.
   Templates

  HTML-based templates that bind DOM with Vue instance data.



  ⚙ Directives

  Special attributes like v-if , v-for , v-model to manipulate DOM.



    Vue-CLI

  Command Line Interface to build and compile projects easily.




 3. Understanding DOM & Virtual DOM

What is DOM (Document Object Model)?
The Document Object Model, or DOM, is an interface that treats all markup language (your HTML) as
connected nodes. It can be seen as an interface of objects for markup elements stored in a tree-like
structure.

The DOM allows us to write and change styles on elements, and even change elements themselves. This is
done by adding, modifying, or deleting element tags or CSS styles in the head and body of a document
because they are represented as nodes and objects.

⚠ Disadvantages of Traditional DOM
As applications grow, more nodes to traverse, more elements, and more scripts to communicate with those
elements — the DOM grows slower and costs a lot of processing power. Trying to perform a search or even
update a DOM becomes a hard task, ultimately affecting the performance of the application.




                                    How Vue.js Virtual DOM Works


        Step 1         Initial Render

      Vue creates a Virtual DOM from the template and renders it to the real DOM.

         Template
        <div id="app">
            <h1>{{ title }}</h1>
            <p>{{ message }}</p>
          <button @click="update">Update</button>
        </div>



                                                     →
         Virtual DOM (in memory)
        • div#app
        •   h1 → "Hello Vue!"
        •    p → "This is Vue.js"
        •    button → "Update"




        Step 2         Data Changes

      When data changes, Vue creates a new Virtual DOM (New VDOM).

         Data Change
        // change
 this.message = 'Virtual DOM is awesome!'




  New Virtual DOM (in memory)
 <div id="app">
   <h1>Hello Vue!</h1>
  <p>Virtual DOM is awesome!</p>
   <button>Update</button>
 </div>




 Step 3       Diffing (Compare)

Vue compares the New VDOM with the Old VDOM to find the minimal changes.

  Old Virtual DOM
 <div id="app">
  <h1>Hello Vue!</h1>
  <p>This is Vue.js</p>
  <button>Update</button>
 </div>



                                                  ↔
  New Virtual DOM
 <div id="app">
  <h1>Hello Vue!</h1>
  <p>Virtual DOM is awesome!</p>
   <button>Update</button>
 </div>




  Diff Result: Only the <p> tag content changed from "This is Vue.js" to "Virtual DOM is awesome!"




 Step 4       Patch

Vue creates a patch (instructions) with only the necessary changes.

  Patch (instructions):
 - Set <p> text to 'Virtual DOM is awesome!'




 Step 5       Apply Patch to Real DOM

Vue applies the patch to the real DOM. Only the changed part is updated.

  Real DOM (in browser)
 <div id="app">
  <h1>Hello Vue!</h1>
  <p>Virtual DOM is awesome!</p>
   <button>Update</button>
 </div>




 Step 6       DOM is in Sync

The real DOM is now in sync with the latest data. UI is updated with minimal
operations.

  Final Real DOM (in browser)
 <div id="app">
  <h1>Hello Vue!</h1>
  <p>Virtual DOM is awesome!</p>
  <button>Update</button>
 </div>




Benefits of Virtual DOM:
        Better Performance
        Minimal DOM operations
        Faster UI updates
        More efficient




       Summary: Vue uses Virtual DOM as an intermediary layer. When data changes, it updates the
      Virtual DOM, compares it with the previous one (diffing), creates a patch, and applies only the
      necessary changes to the Real DOM.

 1. Simple Component – Reusable Building Block


 Theory: Components are independent, reusable pieces of UI. In Vue 3, a component encapsulates HTML
(template), logic (script), and scoped styles. Components help split the UI into manageable pieces and can be
nested. Each component instance maintains its own state when data is a function.

Local registration: import component and add to components option.
Template: defines HTML structure with Vue directives.
Scoped styles: CSS that applies only to this component.




//   src/components/BasicComponent.vue
<template>
    <div class="my-component">
     <h1>This is coming from component</h1>
     <p>Hello! I am a reusable component.</p>
    </div>
</template>


<script>
export default {
    name: "BasicComponent",
};
</script>


<style scoped>
.my-component {
    border: 2px solid green;
    padding: 20px;
    margin: 10px;
    background-color: #e8f5e9;
    border-radius: 10px;
}
</style>


//   App.vue
<template>
    <div id="app">
     <h1>My Vue 3 App</h1>
     <BasicComponent />
     <BasicComponent />
     <BasicComponent />
    </div>
</template>


<script>
import BasicComponent from "./components/BasicComponent.vue";
export default {
    name: "App",
    components: { BasicComponent },
};
</script>




Explanation: The BasicComponent defines a simple card with a heading and paragraph. scoped styles ensure the green
border only affects this component. In App.vue, we import and register the component locally, then use it three times. Each
instance is independent — demonstrating reusability.

 2. Data as a Function – Independent State Isolation


⚠ Critical Concept: In Vue components, data must be a function that returns a fresh object. If it were a plain
object, all instances would share the same reference, causing mutations to affect every component. This
pattern guarantees each instance has its own private reactive scope.

data() { return { count: 0 } } → correct.
data: { count: 0 } → wrong (Vue 3 throws warning).




//   src/components/ClickCounter.vue

    </div>

<script>

 3. Local Registration – Scope & Encapsulation


Local Registration means a component is available only inside the component where it is registered (via
components option). This prevents global conflicts, improves bundle splitting, and makes dependencies explicit.
It's the recommended way for most components.



//   src/components/SpecialButton.vue
<template>
    <button class="special-btn"> Special Button (Local Only)</button>
</template>


<script>
export default { name: "SpecialButton" };
</script>


<style scoped>
.special-btn {
    background-color: purple;
    color: white;
    padding: 10px 20px;
    border: none;
    border-radius: 5px;
    margin: 5px;
    cursor: pointer;
}
</style>


//   src/components/ParentBox.vue
<template>
    <div class="parent-box">
     <h3>Parent Component</h3>
     <p>This component can use SpecialButton because I registered it here:</p>
     <SpecialButton />
     <SpecialButton />
    </div>
</template>


<script>
import SpecialButton from "./SpecialButton.vue";
export default {
    name: "ParentBox",
    components: { SpecialButton },   // LOCAL registration
};
</script>


<style scoped>
.parent-box {
    border: 3px solid blue;
    padding: 20px;
    margin: 10px;
    border-radius: 10px;
}
</style>


// App.vue
<template>
    <div id="app">
     <h1>Local vs Global Registration</h1>
     <ParentBox />
     <!-- <SpecialButton /> would FAIL -->
    </div>
</template>


<script>
import ParentBox from "./components/ParentBox.vue";
export default {
    components: { ParentBox }
};
</script>




Explanation: SpecialButton is only registered inside ParentBox's components option. It works perfectly inside the parent, but
trying to use <SpecialButton/> directly in App.vue would cause a "failed to resolve component" error. This encapsulation
prevents naming collisions.

 4. Global Registration – One-Time, Use Everywhere


 Global Components are registered using app.component('name', Component) in main.js. After registration, they
can be used in any component template without importing. Best for high-frequency UI pieces (alerts, modals,
buttons). Vue 3 migrated from Vue.component to app.component.



//   main.js
import { createApp } from "vue";
import App from "./App.vue";
import GlobalAlert from "./components/GlobalAlert.vue";


const app = createApp(App);
app.component("GlobalAlert", GlobalAlert);   //   GLOBAL REGISTRATION
app.mount("#app");


//   src/components/GlobalAlert.vue
<template>
  <div class="alert-box" v-if="isVisible">
     <div class="alert-icon"></div>
     <div class="alert-content">
      <h3>{{ title }}</h3>
      <p>{{ message }}</p>
     </div>
     <button class="close-btn" @click="closeAlert">✖</button>
  </div>
</template>


<script>
export default {
  name: "GlobalAlert",
  props: { title: { type: String, default: "Notification" }, message: { type: String, default: "This is a global alert component!" }
},
  data() { return { isVisible: true }; },
  methods: { closeAlert() { this.isVisible = false; } }
};
</script>


// App.vue – no import needed!
<template>
  <div id="app">
     <h1> Global Registration Demo</h1>
     <GlobalAlert title="Welcome!" message="Globally registered!" />
     <GlobalAlert title="Special Offer" message="Get 50% off!" />
  </div>
</template>




 Explanation: After app.component(), the GlobalAlert component becomes globally available. You never need to import it in
any component. The alert has internal state (isVisible) and a close button that hides it — demonstrating encapsulated
behavior.

 1. v-if Directive – Conditional Rendering


 Theory: The v-if directive is used to conditionally render a block. The element with v-if will only be
produced if the directive's expression returns a true value. If the expression produces an invalid result (null,
0, empty string, false), the element is deleted from the DOM.

v-if – Renders element only if condition is true
v-else – Renders element when v-if is false (must immediately follow v-if)
v-else-if – Chains multiple conditions




//    Vue 3 Component - VIfDemo.vue
<template>
  <div id="databinding">
      <button @click="showdata" :style="styleobj">Click Me</button>
      <span style="font-size:25px;"><b>{{ show }}</b></span>
      <h1 v-if="show">This is h1 tag</h1>
      <h2>This is h2 tag (always visible)</h2>
  </div>
</template>


<script>
export default {
  name: "VIfDemo",
  data() {
      return {
          show: true,
          styleobj: {
              backgroundColor: "#2196F3",
              cursor: "pointer",
              padding: "8px 16px",
              verticalAlign: "middle",
              border: "none",
              borderRadius: "4px",
              color: "white"
          }
      };
  },
  methods: {
      showdata() {
          this.show = !this.show;
      }
  }
};
</script>




 Explanation: When show is true, the h1 tag is displayed. Clicking the button toggles show to false, and Vue removes the h1
tag from the DOM entirely. The h2 tag is always visible because it has no directive.
⚡ Live Demo: v-if Directive


       Click the button — the h1 tag disappears completely from the DOM when show becomes false.

 4. v-for Directive – List Rendering
 Theory: The v-for directive renders a list of items based on an array. The syntax is item in items where items
is the source array and item is the alias for each element. Note: Vue 3 requires a :key attribute for each
rendered item.



//    Vue 3 Component - VForDemo.vue
<template>
  <div id="databinding">
      <input
          type="text"
          @keyup.enter="showinputvalue"
          :style="styleobj"
          placeholder="Enter Fruits Names"
      />
      <h1 v-if="items.length > 0">Display Fruits Name</h1>
      <ul>
          <li v-for="(a, index) in items" :key="index">{{ a }}</li>
      </ul>
  </div>
</template>


<script>
export default {
  name: "VForDemo",
  data() {
      return {
          items: [],
          styleobj: {
              width: "30%",
              padding: "12px 20px",
              margin: "8px 0",
              boxSizing: "border-box",
              border: "2px solid #ccc",
              borderRadius: "4px",
              fontSize: "16px"
          }
      };
  },
  methods: {
      showinputvalue(event) {
          if (event.target.value.trim()) {
              this.items.push(event.target.value.trim());
              event.target.value = "";
          }
      }
  }
};
</script>




 Explanation: The input field captures fruit names. When Enter is pressed, the value is added to the items array. v-for
iterates over the array and displays each item as a list item. The :key="index" helps Vue track each item uniquely.

    box-shadow: 0 10px 30px rgba(0,0,0,0.2);
}
</style>




Explanation: Instead of writing custom CSS animations, we use Animate.css classes. enter-active-class="animate__animated
animate__swing" applies a swing animation when entering. leave-active-class="animate__animated animate__bounceOut" applies
a bounce-out animation when leaving.

 Transition Classes Reference


Standard Classes (prefixed with transition name):

v-enter – Starting state before element is added
   v-enter-active – Active state during entering (defines delay, duration, easing)
   v-enter-to – Ending state for entering (Vue 2.1.8+)
   v-leave – Starting state for leaving transition
   v-leave-active – Active state during leaving (defines delay, duration, easing)
   v-leave-to – Ending state for leaving (Vue 2.1.8+)

   Custom Class Attributes:

   enter-class – Custom class for entering start state
   enter-active-class – Custom class for entering active state
   enter-to-class – Custom class for entering end state
   leave-class – Custom class for leaving start state
   leave-active-class – Custom class for leaving active state
   leave-to-class – Custom class for leaving end state
